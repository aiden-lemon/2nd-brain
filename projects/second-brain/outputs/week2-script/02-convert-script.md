# 변환 시연 — 발표 대본

> 2주차 교육 · 2026-08-28 · 합니다체 · 온라인 화면 공유
> 담당 구획: 05 사전 요구사항 · 06 1단계 한글 문서 변환 · 07 다른 포맷의 경로

읽는 법:

- 문단은 발화문이다. 그대로 말한다
- `▶` 조작 · `⏸` 쉼 · `▸` 트랙별 덧붙임 · `⚠` 예상 질문 · `🔴` 사고 대비
- **회의 채팅은 쓰지 않는다.** 100% 음성으로 진행한다. 수강자에게 보여줄 문구는 화면에 띄운
  채로 천천히 읽어 주고, 배포 자료에 있다고 안심시킨다. 받아 적게 만들지 않는다
- `▶` 조작에 나오는 **입력창은 전부 Claude Code 프롬프트**다. 회의 채팅창이 아니다
- `⏸`의 초 표기는 호흡이다. 그대로 지킨다

## 05-1 자기 문서가 오늘 되는 경로인지

**화면** — 도구 표 슬라이드

▶ 조작: 슬라이드를 띄우고 마우스 커서를 표의 첫 열에 올려 둔다

지금부터 한동안 제가 화면에서 전 과정을 돌립니다. 지금 따라 하지 않으셔도 됩니다. 보시고,
자기 문서 1건은 과제로 내시면 됩니다.

⏸ 3초. 실습이 아니라는 걸 받아들일 시간.

시작 전에 판단하실 게 하나 있습니다. 오늘 보시는 게 자기 문서에도 바로 되는지입니다. 이게
확장자 하나로 갈립니다.

화면의 표는 다 읽지 않겠습니다. 줄이 다섯 개 있는데 전부 볼 필요는 없습니다. 자기 문서
확장자 한 줄만 찾으시면 됩니다.

⏸ 4초. 각자 자기 줄을 찾을 시간.

찾으셨으면 오른쪽 끝 칸을 보십시오. 오늘 이 머신에서 되는지 안 되는지가 거기 적혀 있습니다.

한글 파일이면 가장 편합니다. 설치가 0건입니다. 한컴오피스도 필요 없습니다. HWPX가 국가표준을
따르는 압축 파일이고, 그 안이 XML이라서 파이썬으로 그냥 열립니다.

PDF도 됩니다. 필요한 도구가 이 머신에 이미 깔려 있습니다. 종이를 스캔한 PDF까지 실증돼
있습니다.

▸ 개발자 — 압축을 풀고 XML을 파싱하는 게 전부입니다. 외부 바이너리 의존이 없습니다
▸ 기획자 — 한글 파일이면 오늘 아무것도 안 깔고 됩니다

⚠ 예상 질문: "윈도우는 어떻게 하나요" → 화면 아래 두 줄이 윈도우용입니다. 설치가 끝나면 새
터미널을 여는 게 중요합니다

🔴 사고 대비: 화면 공유에서 표가 작게 보인다는 반응이 오면 → 표를 확대하고 자기 줄을 찾을
시간을 5초 더 준다

## 05-2 도구가 없으면 아무 일도 일어나지 않는다

**화면** — 같은 슬라이드. 커서를 설치 명령 두 줄로 옮긴다

▶ 조작: 설치 명령 두 줄을 확대한다. 커서를 첫 줄에 올려 둔다

설치 명령은 화면에 띄워 두겠습니다. 지금 깔지 않으셔도 됩니다. 과제 전까지만 하시면 됩니다.

받아 적지 않으셔도 됩니다. 이 두 줄은 배포 자료에 그대로 있습니다.

천천히 한 번 읽어 드리겠습니다. macOS는 brew install uv입니다. 윈도우는 winget install
astral-sh.uv입니다.

```
화면에 띄워 둘 문구 (발표자 참고용)
macOS   : brew install uv
Windows : winget install astral-sh.uv
설치가 끝나면 새 터미널을 엽니다
```

⏸ 5초. 화면의 두 줄을 눈으로 확인할 시간.

윈도우는 설치가 끝나면 반드시 새 터미널을 여십시오. 열려 있던 터미널에는 경로가 잡히지
않습니다. 이걸로 막히는 경우가 제일 흔합니다.

⏸ 2초.

하나 안심하실 부분이 있습니다. 도구가 없으면 변환 스킬은 안내만 하고 멈춥니다. 알아서
설치하지 않습니다.

그래서 준비가 안 된 상태에서 돌려도 문서가 망가지지 않습니다. 아무 일도 일어나지 않습니다.

▸ 개발자 — 전제 도구 확인이 스킬 0단계에 있습니다. 통과하지 못하면 쓰기 자체를 하지 않습니다
▸ 기획자 — 잘못 눌러서 원본이 깨질 걱정은 안 하셔도 됩니다

⚠ 예상 질문: "brew가 없으면요" → macOS는 brew부터 깝니다. 과제 안내 때 설치 링크를 같이
드립니다

🔴 사고 대비: 받아 적을 테니 잠깐 멈춰 달라는 요청이 오면 → 배포 자료와 과제 슬라이드에 같은
문구가 있다고 먼저 안내한다. 그래도 적겠다고 하면 화면을 그대로 두고 5초 더 쉰다

## 06-1 요청 두 줄과 첫 관문

**화면** — 터미널. Claude Code 세션을 미리 띄워 둔다

▶ 조작: 화면을 터미널로 바꾼다. 폰트는 미리 크게 해 둔다

이제 실제로 돌려 보겠습니다.

⏸ 3초. 화면이 바뀐 직후.

먼저 말씀드릴 게 있습니다. 명령어를 외우지 않습니다. 오늘 제가 넣는 건 문장 두 줄입니다.

▶ 조작: Claude Code 입력창에 아래 두 줄을 붙여 넣는다. 엔터는 아직 누르지 않는다

```
이 한글 파일 마크다운으로 변환해서 Clippings에 넣어줘
projects/second-brain/samples/점검-결과-보고.hwpx
```

이게 전부입니다. 첫 줄이 하고 싶은 일이고, 둘째 줄이 파일 경로입니다.

▶ 조작: 입력창의 두 줄이 다 보이게 잠깐 멈춘다. 잘려 보이면 터미널 폰트를 한 단계 더 키운다

⏸ 5초. 화면의 두 줄을 각자 읽을 시간.

받아 적지 않으셔도 됩니다. 이 문구는 과제 슬라이드에 그대로 있습니다. 과제 때는 둘째 줄만
자기 파일 경로로 바꾸시면 됩니다.

엔터를 누르겠습니다. 그런데 바로 변환이 시작되지 않습니다. 질문이 하나 뜹니다.

▶ 조작: 엔터

⏸ 게이트 1 질문이 뜰 때까지 기다린다. 뜨면 커서로 그 문장을 가리킨다.

떴습니다. 이게 첫 번째 관문입니다. 관문은 세 개인데, 사람이 답해야 하는 건 이 하나입니다.

⚠ 예상 질문: "이 문장을 정확히 이렇게 써야 하나요" → 아닙니다. 뜻이 통하면 됩니다. 확장자와
경로만 정확하면 스킬이 걸립니다

🔴 사고 대비: 게이트 질문이 안 뜨고 변환이 바로 시작되면 → 중단하지 않고 그대로 진행시킨다.
"오늘은 질문 없이 넘어갔습니다"로 정직하게 말한 뒤, 게이트 세 개는 슬라이드로 설명한다

🔴 사고 대비: 스킬이 안 걸리고 일반 답변이 나오면 → 세션을 새로 열고 같은 두 줄을 다시 넣는다.
두 번째도 안 되면 슬라이드 화면으로 대체 설명한다

## 06-2 화면 문구를 우리 상황으로 번역한다

**화면** — 게이트 1 질문이 뜬 대화 화면

화면 문구를 그대로 읽어 드리겠습니다. "이 문서는 팀 공유 vault에 커밋 가능한가"입니다.

⏸ 3초.

여기서 어긋나는 게 있습니다. 오늘 교육은 팀 공유 vault가 아닙니다. 각자 자기 private repo에
자기 vault를 만드는 전제입니다. 그런데 화면에는 팀 공유로 뜹니다.

그래서 이 문구를 이렇게 읽습니다. "이걸 git 이력에 영구히 남겨도 되는가"입니다.

⏸ 4초. 번역한 문장이 남게 두는 쉼.

혼자 쓰는 저장소라도 이 질문은 그대로 유효합니다. 커밋은 남습니다.

판단이 어려우면 기준을 하나로 두시면 됩니다. 이 문서가 나중에 누구 눈에 띄어도 곤란하지 않은가
입니다. 곤란하다 싶으면 "아니오"입니다.

▸ 개발자 — 커밋하면 git 이력에 영구히 기록됩니다. 나중에 파일을 지워도 이력에는 남습니다.
저장소를 나중에 공개로 바꾸면 이력째로 같이 열립니다
▸ 기획자 — 판단은 하나만 하시면 됩니다. "회사 밖으로 나가면 안 되는 문서인가"입니다. 고객사
이름이 들어간 문서, 계약서, 개인 정보가 있는 문서면 "아니오"로 답하시면 됩니다

여기서 "아니오"라고 답하면 어떻게 되는지가 더 중요합니다. 거기서 끝나지 않습니다. vault 밖
변환 모드가 있습니다.

⏸ 2초.

이름이 어려운데 뜻은 간단합니다. 변환은 해 주되 위키에는 안 넣는다는 겁니다.

추출과 판정은 똑같이 합니다. 다만 vault 아래에는 아무것도 쓰지 않습니다. 검증 기준도
뒤집힙니다. 산출물이 vault 밖에 있는지를 확인합니다.

"회사 문서를 넣어도 되나"의 답은 정책 문장이 아닙니다. 경로로 준비돼 있습니다.

⏸ 3초. 강조 직후.

이 모드로 만든 결과를 나중에 vault로 옮길 때는, 커밋 전에 diff를 봅니다. 바뀐 부분만 따로
보여 주는 화면입니다. 거기서 연락처, 이메일, 사업자번호, 상세 주소가 섞였는지 확인합니다.
완료 보고에는 어떤 모드로 돌렸는지와 산출 경로가 같이 남습니다.

⚠ 예상 질문: "그럼 고객사 문서는 아예 못 넣나요" → 정식 인제스트는 막힙니다. 변환 자체는 vault
밖 모드로 됩니다. 넣을지는 사람이 diff를 보고 결정합니다

🔴 사고 대비: 화면 문구가 슬라이드와 다르게 표현되면 → 뜬 문구를 그대로 읽고 "표현은 다르지만
묻는 건 같습니다"로 이어서 번역 문장으로 넘어간다

## 06-3 나머지 두 관문

**화면** — 대화 화면

▶ 조작: 게이트 1에 "응, 교육용 샘플이라 괜찮아"로 답한다

교육용 샘플이라 "예"로 답하겠습니다.

⏸ 진행이 지나갈 때까지 2초.

나머지 두 개는 사람이 답할 게 없어서 빨리 지나갑니다. 그래도 무엇을 막아 주는지는 아셔야
합니다.

하나는 어느 vault에 쓸지 확정하는 겁니다. 제가 말한 경로가 1순위입니다. 없으면 지금 폴더
구조를 보고 판단합니다. 그것도 애매하면 물어봅니다. 기본 경로로 조용히 넘어가지 않습니다.

엉뚱한 폴더에 파일이 흩어지는 걸 막는 장치입니다.

다른 하나는 중복 검사입니다. 원본 보관 폴더에 같은 파일명이 이미 있으면 멈춥니다. 덮어쓰지
않습니다. 그 폴더는 추가만 되고 수정이 안 됩니다.

▸ 개발자 — `raw/`는 append-only입니다. 중복이면 쓰기 없이 사유만 보고합니다
▸ 기획자 — 같은 파일을 두 번 넣으면 두 번째는 그냥 멈춥니다. 먼저 넣은 게 지워지지 않습니다

🔴 사고 대비: 중복으로 막히면 → 당황하지 않고 "이게 세 번째 관문이 작동한 화면입니다"로
설명한다. 그 뒤 파일을 지우고 다시 돌린다. 리허설에서 `raw/hwp/점검-결과-보고.hwpx`와 이전
산출물을 미리 지워 둔다

## 06-4 판정에 쓰는 숫자는 하나뿐이다

**화면** — 실행 로그 4줄

▶ 조작: 변환이 돌아간다. 1초 안에 끝나므로 기다림이 거의 없다

끝났습니다.

⏸ 2초. 너무 빨라서 오히려 여기서 한 번 끊는다.

너무 빨라서 놓치셨을 겁니다. 0.465초입니다.

지금 네 줄이 떴는데 다 읽지 않겠습니다. 세 번째 줄만 보시면 됩니다.

▶ 조작: 커서로 `stats` 줄을 가리키고 3초 머문다

⏸ 3초.

거기 숫자 두 개가 판정 근거입니다. 본문 글자 수와 표 개수입니다. 403자에 표 1개입니다. 채택
기준이 300자라서 통과했습니다.

이 값이 미리 적어 둔 기대값과 정확히 같습니다. 오늘 처음 돌려서 운 좋게 된 게 아니라, 같은
결과가 재현된 겁니다.

⏸ 2초.

숫자가 낯설 수 있으니 조금 더 풀어 드리겠습니다.

앞의 숫자는 뽑아낸 본문이 얼마나 되는지입니다. 이게 너무 적으면 문서를 제대로 못 읽었다는
뜻입니다. 그래서 300자라는 하한을 둡니다.

뒤의 숫자는 표를 표로 인식했는지입니다. 1이면 표 하나를 표로 살렸다는 뜻이고, 0이면 표가
사라졌다는 뜻입니다.

▸ 개발자 — 위쪽 줄의 557과 이 줄의 403이 다릅니다. 세는 방식이 다릅니다. 557은 마크다운 전체
길이, 403은 공백을 뺀 본문 글자 수입니다. 판정에 걸리는 값은 403입니다
▸ 기획자 — 숫자는 안 보셔도 됩니다. 표가 표로 나왔는지 눈으로 보시면 됩니다

▶ 조작: 산출 마크다운의 표 부분으로 화면을 내린다

⏸ 3초. 표를 눈으로 볼 시간.

표가 표로 나왔습니다. 설비코드, 점검 항목, 측정값, 판정. 네 칸이 그대로 살아 있습니다.

이게 방금 말씀드린 표 1개의 실체입니다. 숫자를 안 보셔도 이 화면만 보시면 판단이 됩니다.

⏸ 2초.

이 두 숫자가 0이면 위키로 넘기지 않습니다. 표 개수가 0이면 표가 줄글로 풀렸다는 뜻입니다.
제목 개수가 0이면 문서 구조를 잃은 겁니다.

⚠ 예상 질문: "300자 기준은 어디서 나온 값인가요" → PDF 기준을 문서 단위로 빌려 온 초기값입니다.
조정 대상이라고 스킬 문서에 그대로 적혀 있습니다

🔴 사고 대비: `uv`가 의존성을 새로 받아 10초 이상 걸리면 → "지금 파이썬 패키지를 준비하는
중입니다. 이건 처음 한 번만입니다"로 빈 시간을 채운다

🔴 사고 대비: 변환이 실패하면 → 미리 저장해 둔 로그 캡처로 넘어간다. 실패 화면도 그냥 넘기지
않고 "이 경우엔 vault에 아무것도 안 쓰입니다"를 한 번 짚는다

## 06-5 성공 화면 다음에 결함을 본다

**화면** — 산출 마크다운

여기까지만 보면 잘 된 겁니다. 수치도 맞고 표도 살았습니다.

⏸ 3초. 성공을 인정하는 쉼.

그런데 결함이 하나 있습니다.

▶ 조작: 산출 마크다운의 첫 줄로 올리고 그 줄만 확대한다

⏸ 4초. 각자 첫 줄을 읽을 시간.

첫 줄을 보십시오. 부서명이 두 번 들어가 있습니다. 그 사이에 문서 제목이 끼어 있습니다. 세
덩어리가 공백도 없이 붙었습니다.

⏸ 3초.

방금 본 수치는 정상이었습니다. 403자, 표 1개. 그런데 첫 줄은 이렇습니다.

원인이 있습니다. 한글 문서의 머리말과 꼬리말은 본문과 다른 층에 있습니다. 화면에서는 위아래에
따로 떠 있지만, 텍스트로 뽑으면 그 구분이 사라져서 본문에 섞입니다.

여기서 오늘 이 구획의 가장 중요한 문장을 말씀드립니다.

변환은 자동입니다. 검수는 자동이 아닙니다.

⏸ 4초. 이 문장 뒤에는 반드시 쉰다.

위키로 넘기기 전에 두 군데만 보시면 됩니다. 첫 줄, 그리고 표입니다. 이 두 개입니다.

▸ 개발자 — 글자 수 통계로는 안 잡히는 구조 오류입니다. 수치 게이트만 믿으면 그대로 통과합니다
▸ 기획자 — 자기 문서에서도 첫 줄에 회사명이나 부서명이 붙어 나올 확률이 높습니다. 성공 화면만
보면 그냥 지나갑니다

확률이 높다고만 말씀드리겠습니다. 단정하지 않습니다. 이 vault 실측 1건이 지금 있는 근거
전부입니다.

⏸ 2초.

그리고 되돌릴 수 있습니다. 원본이 원본 폴더에 그대로 남아 있습니다. 잘못 만든 노트는 버리고
다시 만들면 됩니다.

⚠ 예상 질문: "이건 손으로 고쳐서 쓰나요" → 이번 실행에서는 위키화를 보류했습니다. 그 판단
기록은 다음 구획에서 보여 드립니다

🔴 사고 대비: 이번 실행에서 머리말 중복이 재현되지 않으면 → 감추지 않는다. "오늘은 안
나왔습니다"로 말하고 08-27 산출물 캡처를 띄운다. 결론 문장은 그대로 유지한다

## 07-1 문제는 한글 파일이 아니다

**화면** — 포맷별 경로 표 슬라이드

▶ 조작: 화면을 슬라이드로 되돌린다

이제 한글 파일이 아닌 경우입니다.

⏸ 3초. 화면 전환 직후.

먼저 짚고 싶은 게 있습니다. 문제는 한글 파일이라는 게 아닙니다. 바이너리라는 사실입니다.

옛날 워드 파일이든 PDF든 엑셀이든, 텍스트 편집기로 열면 깨져 보입니다. 모델도 똑같습니다. 그냥
못 읽습니다. 그래서 앞단에서 읽을 수 있는 형태로 바꿔야 합니다.

포맷이 다르면 바꾸는 방법이 다릅니다. 그래서 경로가 갈립니다.

이 표도 다 읽지 않겠습니다. 자기 문서 줄 하나만 보시면 됩니다. 오른쪽 칸에 오늘 상태가 적혀
있습니다.

⏸ 4초. 각자 자기 줄을 찾을 시간.

한 가지 미리 말씀드립니다. 이 표에는 실증된 것과 실증 안 된 것이 섞여 있습니다. 저는 그 구분을
감추지 않겠습니다.

▸ 개발자 — 앞단 추출이 정확도의 상한을 정합니다. 뒤에서 좋은 모델을 써도 여기서 잃은 건 복구가
안 됩니다
▸ 기획자 — 파일 종류마다 손이 가는 정도가 다릅니다

## 07-2 PDF는 페이지당 300자로 갈린다

**화면** — 같은 표

PDF부터 보겠습니다. PDF는 두 갈래로 갈립니다. 기준은 하나입니다. 페이지당 글자 수 300자입니다.

⏸ 3초.

같은 확장자인데 안이 완전히 다릅니다. 글자로 저장된 PDF가 있고, 종이를 사진으로 찍어 넣은
PDF가 있습니다.

구분하는 방법은 간단합니다. PDF를 열어서 글자를 드래그해 보시면 됩니다. 선택이 되면 글자가
들어 있는 겁니다. 안 되면 사진입니다.

▶ 조작: 샘플 2개의 페이지당 글자 수를 가리킨다

우리 샘플 두 개가 기준선 양쪽에 있습니다. 하나는 페이지당 499자입니다. 글자가 들어 있으니 그냥
뽑습니다. 다른 하나는 0자입니다. 뽑을 글자가 아예 없습니다.

⏸ 3초.

0자짜리는 OCR로 갑니다. 이건 오늘 실증했습니다. 페이지를 이미지로 렌더하고 한글 OCR 모델이
읽었습니다. 표까지 읽혔습니다.

정확도 수치는 말씀드리지 않겠습니다. 기록을 확인하지 못했습니다.

⏸ 2초.

한 가지는 짚고 갑니다. 스캔 PDF에서 조용히 빈 파일이 나오면 그건 결함입니다. 스킬은 0자를
감지하면 멈추고 다른 경로를 제안합니다. 빈 파일을 성공으로 보고하지 않습니다.

▸ 개발자 — 임계 하나로 비싼 경로를 쓸 문서를 먼저 골라냅니다
▸ 기획자 — 종이를 스캔한 것도 됩니다. 다만 글자로 저장된 PDF보다 손이 더 갑니다

⚠ 예상 질문: "OCR 정확도가 몇 프로인가요" → 수치를 확인하지 못했습니다. 오늘은 답하지
않겠습니다. 확인해서 따로 알려 드립니다

## 07-3 오늘 못 보여 드리는 경로

**화면** — 같은 표

이제 정직하게 말씀드릴 부분입니다.

⏸ 2초.

워드 파일은 오늘 라이브로 못 보여 드립니다. 이 머신에 pandoc이 없습니다.

▶ 조작: `.docx` 줄을 가리킨다

원리는 간단합니다. pandoc이 워드 파일을 마크다운으로 바로 바꿉니다. 표와 제목과 목록이
보존됩니다. 중간 단계가 없습니다.

기대값도 있습니다. 제목 6개, 표 1개, 불릿 3개, 이미지 1개, 316자입니다.

⏸ 3초.

이 숫자는 8월 25일 기록값입니다. 오늘 이 자리에서 실증한 값이 아닙니다. 그러니 이 부분은
시연이 아니라 설명으로 들어 주십시오.

⏸ 3초.

확장자가 doc으로 끝나는 옛날 워드 파일은 갈래가 세 개입니다. 그리고 윈도우 실기기에서 검증이
안 됐습니다. 이것도 그대로 말씀드립니다.

⏸ 2초.

마지막으로 하나 덧붙이겠습니다. 포맷을 바꾸는 효과는 정확도만이 아닙니다. 같은 표를 어떤
형식으로 쓰냐에 따라 토큰이 최대 3배까지 차이 납니다. 앞부분에서 본 컨텍스트 예산이 여기서
다시 걸립니다.

⏸ 3초.

정리하겠습니다. 자기 문서가 한글 파일이면 오늘 본 그대로 하시면 됩니다. 워드 파일이면 과제 전에
pandoc을 먼저 깔아 주십시오.

▶ 조작: pandoc 설치 명령 두 줄을 화면에 띄운다

이것도 받아 적지 않으셔도 됩니다. 배포 자료에 있습니다. macOS는 brew install pandoc이고,
윈도우는 winget install JohnMacFarlane.Pandoc입니다.

```
화면에 띄워 둘 문구 (발표자 참고용)
macOS   : brew install pandoc
Windows : winget install JohnMacFarlane.Pandoc
```

⏸ 4초. 화면의 두 줄을 확인할 시간.

▸ 개발자 — pandoc이 없으면 스킬 0단계에서 걸립니다. 안내만 하고 멈춥니다
▸ 기획자 — 자기 문서가 워드 파일이면 설치가 한 번 필요합니다

⚠ 예상 질문: "지금 깔면 오늘 되나요" → 설치는 금방 끝납니다. 다만 오늘 시연 일정에는 넣지
않겠습니다

🔴 사고 대비: "왜 미리 안 깔았나"는 질문이 나오면 → 변환할 문서가 없으면 도구도 없는 게 실제
상태라고 말한다. 감추지 않는다
