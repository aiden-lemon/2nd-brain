## 섹션별 내용과 근거

### 1. 2nd-brain 복습 — 3′
`Clippings/` → `raw/`(원본, append-only) → `wiki/`(LLM이 읽는 정제 노트) 3계층 그림 하나.
1주차에 각자 만든 vault가 지금 어떤 상태인지 확인. 설계 이유 상세는 다루지 않는다.

### 2. 컨텍스트 — 9′ (핵심)
나머지 셋의 근거가 여기서 나온다. 예산 개념이 먼저 서야 3단 로딩도 지연 로드도 설명된다.

- 컨텍스트 창에는 시스템 프롬프트·도구 정의까지 전부 들어간다 (`01` B-2)
- 우리 vault 실측: **자동 로드 7,382 B + 지시로 읽음 13,911 B = 21,293 B**. 첫 글자 전에 이미 찬다
- 이 구분이 핵심이다 — 지시로 읽는 것은 **compaction 후 사라진다**
- `VAULT_RULES.md` 하나가 10,215 B라 자동 로드에서 빼고 필요할 때 읽게 만들었다
- `VAULT_MEMORY.md` 8 KB 상한 중 **33.9%** 사용 — 예산은 감각이 아니라 숫자다

**넣지 않음**: context rot 18모델 벤치마크 · lost-in-the-middle · 토큰 환산(공식 수치 없음)

### 3. Skill — 5′
- 스킬은 파일 하나다 — `SKILL.md` = frontmatter(`name`·`description`) + 본문
- **`description`이 발동 조건이다.** 우리 `ollama-local-models.md`는 프론트매터가 없어 안 걸린다
- 3단 로딩: 메타데이터만 상시 **6,823 B = 전량 188,371 B의 3.6%(1/28)**
- 교보재는 `pdf2md-ingest` — 본문 8.6 KB인데 폴더 42 KB

**넣지 않음**: 스코프 우선순위 · 플러그인 · marketplace · 스킬 제작법(4주차)

### 4. MCP — 3′
- USB-C 비유. 규격이 하나라 붙이는 방법이 하나다
- 우리 vault: `google-workspace.md`가 `uvx workspace-mcp` 한 줄로 Drive·Sheets·Slides를 붙인다
- 대비: `ollama-local-models.md`는 MCP가 아니다 (HTTP API 직접 호출).
  **붙였다고 다 MCP가 아니다**
- 3주차가 이 클라우드 연동이다

**넣지 않음**: 스펙 버전 · 거버넌스 · 보안 5종 공격 · transport 상세

### 5. 환경 확인 — 3′
- 무엇이 있어야 무엇이 되는지: `.hwpx`는 `uv`만으로 된다. `.docx`는 pandoc, PDF는 poppler
- 설치 명령은 화면에 띄우고 채팅에 그대로 적는다

### 6. `.hwpx` 라이브 변환 — 11′ (시연 본체)
설치 없이 되는 유일한 경로라 실패 가능성이 가장 낮다. 천천히, 재현 가능하게.

1. 요청 문구를 채팅에 그대로 적어준다
2. **게이트 3개**: 커밋 가능성 → `VAULT_DIR` → `raw/` 중복. 하나라도 실패하면 아무것도 쓰지 않는다
   - 화면 문구는 "팀 공유 vault에 커밋 가능한가"로 뜬다. **"git 이력에 영구히 남겨도 되는가"로 읽는다**
   - 안 되는 문서에는 vault 밖 변환 모드가 있다 — 정책 문장이 아니라 경로다
3. 판정 수치 확인: `chars=403 tables=1` (0.465초, 의존성 5개 9ms 준비)
4. **머리말 중복 아티팩트 검수** — 이 섹션의 가장 중요한 1분.
   `제3공장 설비팀 — 대외비 아님 (교육용 샘플)압축기 정기 점검 결과 보고제3공장...`
   수치가 맞아도 머리말이 본문에 섞인다. **변환은 자동이지만 검수는 자동이 아니다**

### 7. 다른 포맷의 경로 — 5′
`.docx`는 라이브 아님 — pandoc이 없다. **PDF는 실증됐다** — poppler가 있고 스캔 PDF가
S6 로컬 OCR(`ppu-paddle-ocr` 한글 모델)로 표까지 읽혔다 (2026-08-28 실행).

- `.docx` → D1 pandoc 직행(표·헤딩·목록 보존) · 레거시 `.doc` → D2a/D2b/D2c 분기
- PDF → 페이지당 300자로 갈린다: 텍스트 PDF는 S2 추출, 스캔 PDF는 **S6 로컬 OCR 또는 S4 비전 전사**
- 샘플 2개가 기준선 양쪽에 있다 (499자/페이지 vs **0자**)
- `.docx` 수치는 2026-08-25 기록값이다 — 이 자리에서 실증한 값이 아니라고 밝힌다

### 8. 인제스트 → wiki — 7′
- 변환 스킬은 변환까지만 한다. 위키화는 `vault-ingest`가 이어받는다
- `raw/`에 원본 스냅샷, `wiki/`에 정제 노트, `wiki/INDEX.md`에 색인 915 B
- 왜 2계층인가 — 원본을 그냥 검색에 던지는 방식과의 대비 (`04` §5)
- **인제스트는 들어온 것을 다 위키로 만들지 않는다.** 2026-08-28 실행에서 점검 샘플의 wiki화를
  보류했고 사유를 로그에 남겼다 — "검증 불가능한 도메인 사실이 지식 계층에 들어간다".
  원문은 `raw/`에 변환 파이프라인의 증거로만 보존했다
  (`outputs/runs/2026-08-28-ingest-aiden-lemon.md`). 설명이 아니라 실제 판단 기록이라 강하다

### 9. 업무 활용 — 9′
- `vault-query` — 위키에 물어본다. 노트가 쌓인 뒤에만 의미가 있다고 정직하게 말한다
- **주간 보고서** `areas/weekly/2026-08-28.{md,html}` — 입력이 git 이력이라 사람이 쓸 게 없다.
  커밋 20 · 머지 PR 5 · 40파일 · +3,876/-115 · 신규 스킬 8 · **신규 wiki 문서 0**
- 위키 쪽 요점은 **1주차에 클리핑 1건을 넣었더니 위키 노트 4개가 됐다**는 것이다.
  수강자가 지난주에 한 일의 결과이므로 남의 사례가 아니다
- `claude-subscription-billing-boundary.md`는 `status: needs-update`가 붙어 있다 —
  위키는 완성품이 아니라 갱신 대상이라는 증거로 쓴다
- 트랙별로 다르게 말할 지점은 `05` §3 분기표를 따른다
