## 1. 스킬 17개 — 무슨 일을 시킬 수 있나

`description`은 곧 발동 조건이다. 아래 "말하는 방식" 열은 프론트매터에 적힌 트리거를 그대로 옮긴 것이다.

### 문서를 위키로 넣는 레인 (2주차 주제)

| 스킬 | 하는 일 | 말하는 방식 | 상태 |
| --- | --- | --- | --- |
| `hwp2md-ingest` | .hwp/.hwpx → MD. **한컴오피스 불필요**(H1 순수 Python) | "이 한글 파일 마크다운으로 변환해서 Clippings에 넣어줘" | `uv`만 있으면 동작 (실측 확인) |
| `doc2md-ingest` | .docx/.doc → MD. 표·헤딩·목록 보존(D1 pandoc) | "이 워드 파일 변환해줘" | **pandoc 필요 — 이 머신 미설치** |
| `pdf2md-ingest` | PDF → MD. 페이지당 300자로 텍스트/스캔 판정 | "이 PDF 변환해줘" | **poppler 필요 — 이 머신 미설치** |
| `vault-ingest` / `vault-ingest-once` | `Clippings/`의 MD를 `wiki/` 노트로 컴파일 | "인제스트해줘" | 동작 |
| `vault-ingest-claude` | 위 인제스트를 Claude Code에 위임하는 절차 | (자동) | 동작 |
| `vault-promote` | repo 문서·개인 노트를 vault로 승격, 원문은 `raw/`에 스냅샷 | "/promote", "승격해줘" | 동작 |

변환 스킬 3종은 **변환까지만** 한다. 위키화는 `vault-ingest`가 이어받는다. 이 분리가 2주차
설명의 핵심 구조다.

### 위키를 쓰는 레인 (업무 활용의 본체)

| 스킬 | 하는 일 | 말하는 방식 |
| --- | --- | --- |
| `vault-query` | wiki 기반으로 개념·비교·정리를 답한다 | "vault에서 ~ 정리해줘" |
| `vault-weekly-report` | 지난 1주 변경을 git 전수 통계로 집계해 주간 보고서 작성. `areas/weekly/YYYY-MM-DD.md` + 같은 이름 `.html` 뷰 | "주간 보고", "주간 보고서" |
| `private-note` | `private/YYYY-MM-DD.md` 개인 노트. **git 비추적** | "private 노트 열어줘" |
| `vault-lint` | 모순·고아 페이지·누락 아티클·frontmatter 결함 점검 | (예약 실행 전용) |

`vault-weekly-report`가 업무 활용 시연에 가장 강하다 — 입력이 git 이력이라 사람이 따로 쓸
게 없고, 산출이 바로 보고서다.

### 외부를 붙이는 레인 (3주차 예고)

| 스킬 | 하는 일 | 2주차와의 관계 |
| --- | --- | --- |
| `google-workspace` | Drive·Sheets·Slides를 `workspace-mcp` MCP 서버로 검색·읽기·편집 | **MCP 설명의 실물** — 붙은 서버가 없으면 쓰지 않는다고 스킬이 명시 |
| `github-project-link` | 외부 GitHub repo를 클론하고 vault에 추적 노트 생성 | 개발자 트랙 |
| `github-project-sync` | 추적 노트를 repo 현재 상태와 대조. 반영은 사용자 승인 후 | 개발자 트랙 |
| `ollama-local-models` | 로컬 모델 연동 — **MCP가 아니다** (아래 주의) | **프론트매터 없음 — 발동 안 됨** |
| `ai-studio-project-onboarding` | AI Studio export 앱을 git·vault에 정착 | 개발자 트랙 |
| `parallel-wp-orchestration` | 여러 repo/모듈 작업을 서브 에이전트 병렬 WP로 분해 | 개발자 트랙, 4주차 성격 |

> **주의 — 이 스킬을 MCP 사례로 쓰면 틀린다.** `ollama-local-models.md`에는 MCP가 한 번도
> 등장하지 않는다(`grep -ci mcp` = 0). `curl http://127.0.0.1:11434/api/generate`로 Ollama의
> HTTP API를 직접 호출하는 절차서다.
>
> **역으로 좋은 교육 소재다** — "외부 시스템을 붙였다고 다 MCP가 아니다. API를 직접 호출하는
> 길도 있고, 우리 vault에 실제로 둘 다 있다." MCP를 쓰는 것은 `google-workspace.md`
> (`uvx workspace-mcp`)이고, 직접 호출은 이 스킬이다. 두 방식을 나란히 놓으면 MCP가 무엇을
> 대체하는 규격인지가 선명해진다.

## 2. 업무 활용 시나리오 — 트랙별

수집 시트이므로 "실증됨/미실증"을 구분해 적는다. 미실증 시나리오를 교육에서 단언하지 않는다.

### 비개발자(기획자) 트랙

| 업무 상황 | 시키는 일 | 쓰이는 것 | 실증 |
| --- | --- | --- | --- |
| 전임자가 남긴 hwp 기획서 더미 | 변환 → 위키화 → 질의 | `hwp2md-ingest` → `vault-ingest` → `vault-query` | 샘플로 실증 가능 (H1은 설치 없이 동작) |
| 회의 자료·정책 문서가 메일과 드라이브에 흩어져 있음 | 한곳에 모아 색인 | `Clippings/` → `raw/`+`wiki/` | 실증 가능 |
| "작년에 이거 왜 이렇게 결정했지" | 위키에 질의 | `vault-query` | **위키에 노트가 쌓인 뒤에만 의미 있음** — 2주차 실습으로는 노트 1~2개뿐 |
| 주간 보고 작성 | git 이력으로 자동 집계 | `vault-weekly-report` | 실증 가능 (vault 변경 이력이 있어야 함) |
| 스캔된 종이 문서 | 비전 전사 | `pdf2md-ingest` S4 | poppler 미설치 → **설치 후 확인 필요** |
| 고객사 자료라 커밋하면 안 됨 | vault 밖 변환 모드 | 변환 스킬 3종의 커밋 게이트 | 스킬에 경로 존재, 시연 필요 |

### 개발자 트랙

| 업무 상황 | 시키는 일 | 쓰이는 것 | 실증 |
| --- | --- | --- | --- |
| repo 문서가 낡아 신뢰 못 함 | 재사용 개념만 위키로 승격, 원문은 `raw/`에 스냅샷 | `vault-promote` | 스킬 존재 |
| 여러 repo 상태 파악 | vault에 추적 노트로 등록·동기화 | `github-project-link` / `-sync` | 스킬 존재 |
| 반복 절차를 매번 설명하기 지침 | 절차를 `SKILL.md`로 고정 | 스킬 작성 | **4주차 주제** |
| 컨텍스트가 금방 찬다 | 규칙 파일 예산 관리, 3단 로딩, sub-agent 격리 | `VAULT_RULES.md` 8 KB 상한, 스킬 3.6% 상시 로드 | 실측값 있음 (`00-internal-metrics.md`) |

## 3. 두 트랙이 갈리는 지점 (같은 화면, 다른 설명)

| 지점 | 개발자에게 | 기획자에게 |

| `raw/` append-only | git 이력·불변 보관 계약 | "원본은 절대 안 건드린다 — 잘못 정리해도 되돌릴 수 있다" |

## 4. 실증 결과 (2026-08-27 이 머신에서 직접 실행)

### `.hwpx` H1 경로 — 설치 없이 동작함 (실증 완료)

```
$ uv run config/skills/hwp2md-ingest/scripts/h1-extract.py \
    samples/점검-결과-보고.hwpx <scratch>/out.md
Installed 5 packages in 9ms
wrote 557 chars -> <scratch>/out.md
stats chars=403 tables=1 images=0 encrypted=False
실행 시간 0.465s
```

- **한컴오피스 없이, pandoc 없이, 사전 설치 없이 동작한다.** `uv`가 의존성 5개를 9ms에 준비했다
- `chars=403 tables=1` — `samples/README.md`의 기대값(표 1 · 403자)과 **정확히 일치**
- 표가 마크다운 표로 재구성됐다: `| 설비코드 | 점검 항목 | 측정값 | 판정 |` 4행
- vault 밖 scratch로 출력해 `raw/`·`Clippings/`를 건드리지 않았다

**교육에 쓸 주장**: 실습 첫 타깃은 `.hwpx`다. 설치가 안 끝난 수강자도 바로 성공 경험을 얻는다.

### 같은 실행에서 발견한 변환 아티팩트 (검수 필요성의 실증)

산출 MD 첫 줄에 머리말이 본문 제목과 붙어 중복됐다:

```
제3공장 설비팀 — 대외비 아님 (교육용 샘플)압축기 정기 점검 결과 보고제3공장 설비팀 — 대외비 아님 (교육용 샘플)
```

**교육에 쓸 주장**: 변환은 자동이지만 검수는 자동이 아니다. `chars`·`tables` 수치가 맞아도
머리말·꼬리말이 본문에 섞이는 일이 있다. 위키로 넘기기 전에 눈으로 한 번 본다. 이 사례를
실습에서 그대로 쓴다 — 실패 사례를 미리 보여주면 수강자가 자기 문서에서 알아챈다.

### 커밋 게이트 화면 문구 (원문 인용 — `hwp2md-ingest/SKILL.md:46`)

> **커밋 가능성**: 사용자에게 확인 — "이 문서는 팀 공유 vault에 커밋 가능한가?"
> 고객사·개인 문서면 정식 잉게스트는 중단한다. 변환 자체가 필요한 경우에는
> § vault 밖 변환 모드를 제안하고, 사용자가 그 모드를 명시적으로 선택한 경우에만 진행한다.

게이트 3개는 순서가 있다: ① 커밋 가능성 → ② `VAULT_DIR` resolve → ③ `raw/` 중복 검사.
하나라도 실패하면 **아무것도 쓰지 않고 보고**한다 (fail-closed).

> **교육 자료 작성 시 주의**: 이번 교육은 각자 개인 private repo에 자기 vault를 만드는
> 전제다. 화면에는 "팀 공유 vault"라고 뜨므로, 문구는 그대로 인용하고 **"git 이력에 영구히
> 남겨도 되는가"로 읽는다**고 덧붙인다. 화면과 자료가 어긋나면 실습에서 혼란이 난다.

### vault 밖 변환 모드 (고객사·개인 문서용 공식 경로)

`hwp2md-ingest/SKILL.md:123-131` 기준.

- 게이트 3(중복 검사) 생략, 추출·판정은 동일 수행, **vault 아래에 아무것도 쓰지 않는다**
- 검증 기준이 "산출 경로가 `$VAULT_DIR` 밖인가"로 뒤집힌다
- 산출 MD는 파생 작업 입력으로만 쓰고, 파생 결과가 vault로 들어갈 때는 커밋 전에
  개인정보(연락처·이메일·사업자번호·상세 주소) 미유입을 **diff 기준으로** 검증한다
- 완료 보고에 모드 명칭과 산출 경로를 명시한다

**교육에 쓸 주장**: "회사 문서를 넣어도 되나"에 대한 답은 정책 문장이 아니라 경로다.
안 되는 문서에는 vault를 건드리지 않는 별도 경로가 있다.

### `.hwp`/`.hwpx` 정확도 근거 (`hwp2md-ingest/SKILL.md:142-149`, 2026-08-21 실측)

- 실문서 1건(계획서 149 KB · 표 12개)을 vault 밖 변환 모드로 검증
- 같은 문서의 hwp 산출 vs pdf(S2) 산출 정규화 유사도 **94.7%**
- 수치 지문 hwp 측 **전량 일치**. pdf 측 유일 불일치 1건은 pdf 추출의 셀 분할 아티팩트로,
  hwp 쪽이 온전했다
- 원본 PDF 1페이지 시각 대조 핵심 사실 **16/16 일치**. 병합 셀 표도 md 표로 유지

**교육에 쓸 주장**: hwp 경로는 감이 아니라 교차 검증된 수치가 있다. 그리고 같은 문서라면
hwp 원본이 pdf보다 더 정확하게 추출된다.
