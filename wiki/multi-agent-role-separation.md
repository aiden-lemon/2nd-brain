# Multi-Agent Role Separation

## Summary

하나의 모델을 하나의 채팅 창에 밀어넣고 전부 시키는 대신, 오케스트레이터·메인 추론
모델·전문 작업자·인터페이스·실행 환경을 서로 다른 도구에 나눠 맡기는 구성 패턴이다.
출처의 사용자는 이 전환 뒤에야 설정이 "챗봇 루프가 아니라 팀처럼" 돌아갔다고 보고한다.

## Details

출처가 제시하는 역할 배분은 다섯 층이다.

| 역할 | 담당 |
| --- | --- |
| 오케스트레이터·자동화 계층 | [[hermes-agent]] |
| 메인 에이전트 모델 | OpenAI Codex |
| 구독 기반 코딩 전문가 | [[claude-code]] |
| 원격 제어 인터페이스 | Telegram |
| 실행 환경 | 로컬 머신 (파일·cron·이메일·셸·Home Assistant) |

작업 흐름은 네 단계다. 사용자가 오케스트레이터에게 요청 → 오케스트레이터가 직접 처리할지
코딩 부분을 전문가에게 위임할지 판단 → 전문가가 코드 작성·검토·수정 → 오케스트레이터가
결과를 확인하고 간단한 테스트를 돌린 뒤 보고.

역할을 나누는 근거는 각 도구가 잘하는 일이 다르다는 것이다. 오케스트레이터 쪽은 메모리,
도구, 예약 작업, 메시징을 갖고 실제로 머신에서 작업을 수행하는 능력이 강점이고, 코딩
전문가 쪽은 범위가 좁혀진 코딩 작업에 강하다.

출처는 로컬 LLM(Ollama)으로 전부 대체하려는 시도를 대안으로 검토했다가 접었다.
기술적으로는 동작했지만 에이전트 전체 사용에는 너무 느렸다는 것이다. 다만 이는 출처
작성자의 하드웨어 조건에서의 관찰이며 일반적인 성능 결론으로 읽을 근거는 없다

  댓글에서 한 사용자는 라우팅 로직을 손보지 않으면 모든 작업이 메인 모델에서 실행되고 오프로드가
  일어나지 않는 문제를 보고했다.
